# Архитектура

Нагрузка: 1000–1500 участников, до ~100 одновременно. Приоритет — простота и надёжность.

## Схема

```
Телефон / ноутбук ──►  Next.js (один процесс Node.js)
                          ├─ страница сайта (React, клумба на Canvas)
                          └─ /api/[action]  ── lib/core/engine.ts (правила)
                                                 └─ lib/server/store.ts → data/klumba.json
```

* **Почему не Supabase.** Раньше планировался облачный Supabase, но из России он работает нестабильно,
  а школьные сети и «белые списки» мобильных операторов его могут не пропускать. Свой небольшой сервер
  на российском хостинге проще, надёжнее и бесплатен по лимитам: всё в одном процессе, без внешних сервисов.
* **Данные** — одно JSON-состояние (`lib/core/state.ts`) в памяти процесса. После каждого изменения оно через
  150 мс атомарно записывается в файл (временный файл + rename), раз в 10 минут — резервная копия.
  При остановке сервера несохранённое дописывается.
* **Гонки невозможны.** Все изменения синхронные и выполняются в одном потоке Node.js по очереди,
  поэтому два одновременных запроса с одним кодом или на одно место не могут пройти оба.
* **Места на клумбе** генерируются детерминированно (`lib/garden/slots.ts`, ~2000 мест): сервер и браузер
  получают одинаковый список, хранить его не нужно.
* **Обновления в реальном времени** — лёгкий опрос `GET /api/updates?after=<id>` раз в 4 секунды,
  только пока вкладка открыта. Ответ — только новые цветы и номер версии. Если версия выросла (админ
  изменил статус, учителей, удалил учителя), страница перезагружает клумбу целиком — так пропадают удалённые цветы.
  Опрос работает через любые прокси и фильтры, в отличие от WebSocket.
* **Демо-режим** (`lib/api/demo.ts`) использует тот же `engine.ts`, но хранит состояние в памяти браузера.

## Роли

| Кто | Как входит | Что может |
|-----|-----------|-----------|
| Гость | — | смотреть клумбу |
| Ученик | 10-значный код (или QR с `?code=`) | посадить один цветок |
| Учитель | личный код | открыть открытку, увидеть свои цветы |
| Директор | личный код (отдельная кнопка «Вход для директора») | золотая открытка, центральный подсолнух — её |
| Администратор | пароль `ADMIN_PASSWORD` в окне «Вход» | всё в админ-панели |

Пароль администратора в браузер не попадает. После входа выдаётся ключ сессии `admin.<срок>.<HMAC>`,
подписанный секретом из `data/secret.key` и паролем: смена пароля сразу отзывает все сессии.

## Структура

```
app/api/[action]/route.ts   HTTP API (GET garden|updates|slots|health, POST login|plant|card|admin-*)
lib/core/                   state (модель данных), engine (правила), demoSeed (демо-данные)
lib/server/                 store (файл данных), security (пароль, сессии, ограничение попыток)
lib/api/                    клиент: live (сервер) и demo (в браузере), общий интерфейс в types.ts
lib/garden/                 движок клумбы без React: renderer, sprites, flowers, lawn, slots, catalog
lib/qr.ts                   QR-коды, карточки кодов и плакат для печати
components/                 site, garden, planting, account, postcard, admin
```

## Производительность

* Цветы рисуются готовыми спрайтами, кадр перерисовывается только при изменениях.
* Подсказка над цветком обновляется только при смене цветка под курсором, а не на каждое движение мыши.
* Пейзаж за клумбой — статичный SVG. Самолёт и флаг — отдельные слои, их браузер двигает на видеокарте
  (transform), не перерисовывая фон.
* Несколько частей страницы, запросивших снимок клумбы одновременно, получают один общий запрос.
