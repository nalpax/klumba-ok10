# Этап 1. Архитектура

Проект: интерактивная клумба ко Дню учителя. Один код — один цветок, все видят посадки в реальном времени.
Нагрузка: 1000–1500 участников, ~100 одновременно. Приоритет — простота и надёжность.

## 1. Общая схема

```
Телефон / ноутбук ──► Next.js (Vercel)            публичный сайт + /admin
        │                    │
        │  anon-ключ (RLS)   │  сессия администратора (Supabase Auth)
        ▼                    ▼
   Supabase ─ Postgres (таблицы + RLS + функции check_code / plant_flower / get_garden)
            ─ Realtime (новые цветы, смена статуса)
            ─ Storage (teachers, flowers, gallery, video)
            ─ Auth (только администраторы)
```

* Клумба рисуется в **Canvas** (`lib/garden`), без React: один `<canvas>`, готовые спрайты цветов, перерисовка только по необходимости.
* Посадка — **одна функция в базе** `plant_flower(код, учитель, цветок)`. Сайт не может обойти проверки, потому что таблицы для записи ему закрыты.
* Администратор работает через тот же anon-ключ, но с JWT администратора; права ему даёт RLS (`is_admin()`), а не код на клиенте.

## 2. Проблемы, найденные до реализации, и как они решены

| # | Проблема | Решение |
|---|----------|---------|
| 1 | **Доступность из России.** Часть источников сообщает, что облачный Supabase без VPN работает нестабильно (запросы «висят»), другие — что работает. Vercel: адрес `*.vercel.app` обычно открывается, на своём домене возможны проблемы. Мобильный интернет при «белых списках» открывает только разрешённые сайты. | **Проверить до разработки** (шаг 0 в README): открыть проект Supabase с телефонов на МТС, МегаФон, Билайн, Т2 и в школьном Wi-Fi. Если не открывается — запасной вариант: VPS в РФ с обратным прокси к Supabase или полный перенос на свой сервер (схема — обычный Postgres, переносится). |
| 2 | **Лимит 1000 строк.** Supabase API по умолчанию отдаёт максимум 1000 строк за запрос: при 1500 цветах клумба тихо потеряла бы 500 цветов. | Клумба читается функцией `get_garden()`, которая возвращает **одно значение jsonb** (лимит строк не действует) в компактном виде, ≈25 КБ по сети. |
| 3 | **Гонка при выборе места.** Если координаты считает браузер, два ученика одновременно получат одну точку, а «плохому» клиенту можно подставить любые числа. | Места заранее созданы в таблице `garden_slots` (~2000 шт., естественная неровная расстановка). `plant_flower` берёт случайное свободное место через `FOR UPDATE SKIP LOCKED` — параллельные посадки получают **разные** места. Цветы не в сетке и не пересекаются полностью. |
| 4 | **Цвет и картинка цветка.** Цвет задаёт учитель, а вид цветка — администратор. Загруженная PNG/WebP не перекрашивается. | Встроенные цветы (тюльпан, роза, мак, ромашка, василёк, подсолнух) рисуются кодом и **красятся в цвет учителя**. Свои цветы: SVG с `currentColor` перекрашиваются, PNG/WebP рисуются как есть (этап 9). Цвет фиксируется в `plantings.color` в момент посадки. |
| 5 | **Realtime может терять события** (телефон уснул, сеть моргнула). Бесплатный план: 200 одновременных соединений, 2 млн сообщений в месяц. | После переподключения клиент делает `get_garden(последний_id)` и **догоняет** пропущенное. Для 100 пользователей и 1500 цветов лимиты с большим запасом. |
| 6 | **Видео.** Хранилище free-плана — 1 ГБ, исходящий трафик 5 ГБ/мес: 1000 просмотров ролика в 30 МБ — это 30 ГБ. Лимит размера файла на free-плане — 50 МБ, поэтому «100 МБ» из задания не пройдёт. | Лимит бакета `video` — 50 МБ; рекомендую ≤ 15–20 МБ (720p, H.264). На странице `preload="none"` (грузится только по нажатию), без автозвука. Альтернатива без нагрузки на Supabase — ссылка на видео (VK Видео, RuTube, YouTube). |
| 7 | **Пауза проекта.** Бесплатный проект Supabase засыпает после 7 дней без запросов. | Открыть проект и заходить на сайт в неделю перед праздником; проверить накануне. |
| 8 | **Перебор кодов и русская раскладка.** | Код: 8 знаков из 32 (~1,1·10¹² вариантов) при 1500 живых кодах — угадать практически нереально; плюс блокировка после 100 неудачных вводов за 10 минут с адреса (порог высокий: класс сидит за одним Wi-Fi). Ввод нормализуется: пробелы и дефисы убираются, кириллические А, В, Е, К, М, Н, Р, С, Т, Х читаются как латинские. |
| 9 | **Закрытие мероприятия.** | Проверка `events.status = 'open'` внутри `plant_flower` — кнопку на сайте можно обойти, функцию нельзя. Время «начало/окончание» — только для показа. |
| 10 | **Персональные данные.** Имена и фото учителей — персональные данные, база за рубежом (152-ФЗ). | От учеников ничего не собирается. Для учителей нужно их согласие на публикацию фото и имени; вопрос локализации данных — к администрации школы. |

## 3. База данных

```
events (1 строка)          greeting (1 строка)
teachers ──< teacher_flowers >── flowers
    │                               │
    └──────< plantings >────────────┘        plantings.slot_id ──► garden_slots (taken)
                 ▲
participation_codes.planting_id            media        admins        code_attempts
```

* `participation_codes` — коды (`unused` / `used`), связь с цветком лежит **здесь**, а не в `plantings`: посетители читают `plantings`, и связь «код ↔ цветок» им видеть не нужно.
* Код гасится одним `UPDATE … WHERE status = 'unused'`. Два запроса с одним кодом: второй ждёт первого, видит `used` и получает «код уже использован». Дополнительная страховка — `UNIQUE` на `slot_id` и `planting_id`.
* Удаление учителя или цветка, у которых есть посадки, запрещено (`ON DELETE RESTRICT`): их нужно **скрывать**, а не удалять.

## 4. Модель безопасности

| Кто | Что может |
|-----|-----------|
| Посетитель (`anon`) | читать событие, поздравление, учителей, цветы, посадки, активные медиа; вызывать `check_code`, `plant_flower`, `get_garden`. Больше ничего. Таблицы кодов, мест и попыток для него не существуют. |
| Администратор | всё остальное — через RLS `is_admin()` (запись в `admins`), плюс админские функции (`admin_generate_codes`, `admin_export_codes`, `admin_timeline`, `admin_stats`). |
| Секретные ключи | `service_role` проекту не нужен и в код не попадает. В браузер уходит только публичный anon-ключ. |

Регистрация в Supabase Auth должна быть **выключена** (Authentication → Sign In / Providers → отключить «Allow new users to sign up»); администратора вы создаёте вручную.

## 5. Структура проекта

```
app/                     страницы Next.js (layout, page, позже /admin)
components/
  site/                  Header, Hero, GreetingCard, HowItWorks, GardenSection, Footer, SchoolBadge, Leaf
  garden/                Garden (canvas + управление), FlowerPreview, useDemoGarden
lib/
  garden/                движок клумбы без React: renderer, sprites, flowers, lawn, demo, constants
  content.ts             тексты по умолчанию
styles/site.css          стили публичного сайта (привязаны к .site, админку не затрагивают)
public/                  brand/ (подсолнух ОК10), hero/ (открытка)
supabase/migrations/     0001 схема → 0002 безопасность → 0003 функции → 0004 начальные данные
docs/                    эта архитектура, референсы, скриншоты
```

Публичный сайт — рукописный CSS (нужна художественная точность), админка (этап 8) — Tailwind-утилиты.

## 6. Дизайн

* Фон и подача — из зелёного референса: тёмный мох, стеклянные карточки, лаймовый акцент, засечный курсив для заголовков (Lora), гротеск (Manrope).
* Первый экран — осенняя открытка как центральный объект; листья падают позади. Школьный жёлтый (ромб с книгой из баннера) и подсолнух ОК10 — знаки школы.
* Клумба — овальный газон как в референсе с тюльпанами; **подсолнух ОК10 растёт в центре** и остаётся на месте, пока клумба заполняется.
